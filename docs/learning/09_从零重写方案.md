## 1. 目标与范围

重写 [beacon-cloud](https://github.com/justdoit712/beacon-cloud) 短信平台全部代码，技术底座直接使用新栈（非升级）：

| 项 | 值 |
| --- | --- |
| 技术栈 | JDK 17 + Spring Boot 3.2.12 + Spring Cloud 2023.0.3 + Alibaba 2023.0.3.2（版本已冻结在父 POM，2.0.0-SNAPSHOT） |
| 后端 | 9 个模块全部重写（`backend/beacon-*`） |
| 前端 | 运营后台全部重写（`frontend/`，Vue3 + TS + Vite + Element Plus） |
| 不重写 | 数据库表结构（复用 `duanxin_pingtai` 18 张表）、CMPP 协议本身、外部客户接入契约（`/sms/single_send`） |

**与迁移式的本质区别**：迁移式是"旧代码升级"，重写是"按规格书重做"。38 项已知缺陷**边写边规避**，不再单独设阶段三；JDK 17 新特性从第一行代码起强制落地。

## 2. 执行纪律（继承 AI 编写规范，此处收口重写专用规则）

1. **一个模块一个 commit**（`feat(模块): 描述`），每模块必须 `mvn -pl <模块> -am install` 全绿（含单测）才进下一个模块。
2. **只做被要求的事**：按本蓝图逐模块推进，不顺手扩scope；新需求先记 PROGRESS。
3. **证据优先**：不确定的 API/版本先查 Maven Central / 官方文档，禁止编造。
4. **新代码必须带单测**（纯 POJO/record 可豁免）；核心链路（校验链/策略链/路由/扣费/幂等）必须有测试。
5. **敏感信息一律 `${...}` 占位 + Nacos**，禁止明文入库；日志禁止打印短信内容与密钥。
6. **每落一个 JDK 17 特性**，在 `docs/learning/` 对应笔记末尾补一行实战记录（延续"边写边学"）。

## 3. 系统规格摘要（重写的业务蓝图）

> 详细规格以 `../02_项目详细分析总报告.md`、`../03_项目架构与开发指南.md` 为准，此处只列重写必须遵守的骨架。

### 3.1 参与方与模块划分（5 层 9 模块）

| 层 | 模块 | 一句话职责 |
| --- | --- | --- |
| 接入层 | beacon-api | 受理客户/内部发送请求，校验链，投递 MQ |
| 接入层 | beacon-webmaster | 运营后台（Sa-Token 认证）+ 控制平面（余额/缓存同步/代发/检索） |
| 策略层 | beacon-strategy | 策略链：黑名单/敏感词/限流/扣费/号段/携转/路由 |
| 网关层 | beacon-smsgateway | CMPP 2.0 over Netty 下发与回执处理 |
| 日志/回调层 | beacon-search | ES 8 写日志/更新状态/检索统计 |
| 日志/回调层 | beacon-push | 客户状态回调（延迟重试） |
| 支撑层 | beacon-common | 共享模型/常量/异常/工具/缓存域契约 |
| 支撑层 | beacon-cache | 统一 Redis HTTP 服务（签名鉴权 + 命名空间） |
| 支撑层 | beacon-monitor | xxl-job 队列积压/余额巡检 + 邮件告警 |

### 3.2 主链路（必须原样保住的业务闭环）

```text
客户系统 --POST /sms/single_send--> beacon-api（校验链 apikey→ip→sign→template→mobile→fee）
   --MQ sms_pre_send--> beacon-strategy（策略链 black→dirtyword→limit→fee→phase→transfer→route）
   --MQ sms_gateway_{channelId}--> beacon-smsgateway（CMPP Submit → SubmitResp → Deliver）
      |-- MQ sms_write_log --> beacon-search 写 ES
      |-- MQ sms_push_report --> beacon-push 回调客户（延迟重试）
      `-- normal 交换机 --TTL 10s--> dead 队列 --> beacon-search 更新 ES 状态
beacon-webmaster：代发走 api 内部接口；检索/统计 Feign 调 search；主数据落 MySQL 并同步 Redis
```

### 3.3 核心数据对象（重写设计）

| 对象 | 设计 | 说明 |
| --- | --- | --- |
| `StandardSubmit`（common） | **Lombok `@Data` 类（可变）** | 链路中逐过滤器填充（phase 补 operatorId、route 填 channelId），record 会导致每步 copy 噪音；MQ 反序列化友好。字段与旧版一致：sequenceId/clientId/uid/apiKey/mobile/text/sign/signId/state/sendTime/fee/operatorId/areaCode/area/srcNumber/channelId/reportState/errorMsg/realIp/ip/isTransfer |
| `StandardReport`（common） | **`@Data` 类（可变）** | 回执/回调载体：sequenceId/apiKey/clientId/uid/mobile/sendTime/reportState/errorMsg/isCallback/callbackUrl/resendCount/reUpdate |
| Form/VO/DTO | **一律 `record`** | 如 `record SingleSendForm(@NotBlank String apikey, @NotBlank String mobile, String text, Integer state, String uid) {}` |
| 结果类型 | **sealed + record** | 落地候选：`BalanceCommandResult`（扣费成功/失败）、路由判定、缓存读写结果、CMPP 应答解析 |
| 配置类 | **record + 构造器绑定** | `@ConfigurationProperties(prefix="cmpp") record CmppGatewayProperties(...)`；`@RefreshScope` 的类禁用 record |

### 3.4 RabbitMQ 拓扑（重写版收口，单一事实源）

| 名称 | 类型 | 拥有者（唯一声明方） | 生产者 → 消费者 |
| --- | --- | --- | --- |
| sms_pre_send_topic | 持久队列 | beacon-api | api → strategy |
| sms_gateway_topic_{channelId} | 持久队列（动态） | beacon-strategy | strategy → smsgateway |
| sms_write_log_topic | 持久队列 | beacon-search | strategy/smsgateway → search |
| sms_push_report_topic | 持久队列 | beacon-push | strategy/smsgateway → push |
| sms_gateway_normal_exchange/queue + dead_exchange/queue | fanout + TTL 10s + DLX | beacon-smsgateway（**只此一处**，search 不再重复声明） | smsgateway → search |
| push_delayed_exchange/queue | x-delayed-message（**durable=true**）+ fanout | beacon-push | push 自投自收 |

**重写修正项**（对应 05 文档 17 项问题）：命名改为 `*_queue` 为队列、`*_exchange` 为交换机（常量注释写明语义）；`mandatory=true` + confirm/return 回调做补偿记录；状态更新链路统一发 exchange；TTL/重试间隔外置配置；监听容器统一显式配置 ack/prefetch。

### 3.5 Redis 缓存键约定（common 的 CacheKeyConstants + 9 域契约）

沿用旧版契约体系（`CacheDomainRegistry` 重写为 record 化元数据）：
`client_business:{apikey}` / `client_sign:{clientId}` / `client_template:{signId}` / `client_channel:{clientId}` / `channel:{id}` / `client_balance:{clientId}` / `transfer:{mobile}` / `black:{mobile}`（+`black:{clientId}:{mobile}`）/ `dirty_word`；网关态：`cmpp:submit:{seq}`（TTL 600s）、`cmpp:deliver:{msgId}`（TTL 86400s）；验证码：`captcha:{uuid}`（TTL 300s）；限流 zset：`limit:minutes/hours/days:{clientId}:{mobile}`。
命名空间前缀：`beacon:dev:beacon-cloud:cz:`（NamespaceKeyResolver 幂等前缀）。

### 3.6 接口契约（对外兼容，内部收口）

| 接口 | 约定 |
| --- | --- |
| `POST /sms/single_send`（api，外部） | 请求 `{apikey,mobile,text,state,uid}`；返回 `{code:0,msg,uid,sid}`；业务错误 HTTP 200 + code（兼容旧客户） |
| `POST /sms/internal/single_send`（api，内部） | 头 `X-Internal-Token`（**必须非空且恒时比较**，不再默认空放行） |
| `POST /internal/balance/debit`（webmaster） | 同上令牌化；原子扣减（MySQL `debitBalanceAtomic`）+ 余额域缓存刷新 |
| `POST /sys/login` / `GET /sys/auth/captcha`（webmaster） | Sa-Token：`satoken` 头；验证码 `{uuid, img(base64)}` 存 Redis TTL 300s；登录返回 token |
| `POST /search/sms/list`、`/search/sms/countSmsState`（search） | **必须租户隔离**（强制 clientID 过滤）+ 分页上限（from+size ≤ 10000） |
| 统一返回体 | `{code,msg,data}`，code=0 成功；认证失败 HTTP 401、无权限 403、参数错误 400（webmaster 内部收口），对外 api 业务错误维持 200+code |

### 3.7 数据库（不重写，复用 `duanxin_pingtai` 18 张表）

sms_user / sms_role / sms_menu / sms_user_role / sms_role_menu、client_business / client_balance / client_channel / client_sign / client_template、channel、mobile_black / mobile_dirtyword / mobile_transfer / mobile_area、code_limit、schedule_job / schedule_log。字段以旧 Mapper XML 为准；**修正项**：channel 密码列加密存储（数据库改列，代码侧加解密）、`client_business.extend1` 归属关系建模待阶段三（暂不重构表结构）。

## 4. 模块顺序与依赖

```text
R1 common ──┬─▶ R2 cache ──▶ R3 search ──▶ R4 api ──▶ R5 strategy ──▶ R6 push
            └─▶ R7 smsgateway（可与 R2~R6 并行，仅依赖 common）
            └─▶ R8 monitor（仅依赖 common，可随时并行）
R9 webmaster（依赖 common；Feign 依赖 api/search/cache 的契约）
R10 frontend（依赖 R9 的接口契约）
```

原则：**common 是所有人的底座必须最先**；cache 简单先做验证"新栈 + 编译 + 单测"流程；search 是最大独立单点（ES8 全新型代码）；webmaster 最大放最后；前后端契约（satoken 头、验证码接口）在 R9/R10 成对落地。

## 6. 关键横切设计决策（重写版定稿）

| 主题 | 决策 |
| --- | --- |
| MQ 可靠性 | 全部手动 ack；业务失败 ack + 旁路补偿（写日志+回执）；系统异常 nack + 告警；生产者 mandatory + confirm/return 补偿；延迟统一用 TTL+DLX（内部状态更新）与 x-delayed-message（回调重试）两条链，参数外置 |
| ES | 显式 mapping；索引按业务时间路由（IndexNameResolver）；幂等写入；查询强制租户 + 分页上限；更新显式传参 |
| 认证 | 对外 API：apikey + 校验链（业务认证，无 JWT）；内部接口：X-Internal-Token 必填；后台：Sa-Token（token 存 Redis，可踢人下线）+ 权限码=菜单 url |
| 扣费 | MySQL 原子更新（debitBalanceAtomic）为唯一真源，成功后刷新余额缓存域；route 失败冲正；透支额度配置化 |
| 限流 | cache 侧 Lua 原子（zadd+zcount+zremove 一步完成）；阈值/窗口配置化；仅验证码类生效 |
| 线程池 | smsgateway 两个池标准 ThreadPoolExecutor（容量 `${cmpp.pool.*}` + CallerRunsPolicy）；Bean 名 `cmppSubmitPool`/`cmppDeliverPool` 固定 |
| 配置 | 全部外置 `${...}` + Nacos `{app}-dev.yml`；仓库只保留 bootstrap.yml（Nacos 地址 + 本地开发默认值） |
| 包结构 | `com.cz.{module}`，子包 controller/service(.impl)/mq/client(.dto)/config/filter/dto|vo|form/util/entity|mapper（AI 规范 §4.9） |
| 结果类型 | sealed+record 落地点：BalanceCommandResult、路由判定、CMPP 应答解析、缓存读写结果 |
