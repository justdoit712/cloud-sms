# 08 · 前后端架构与目录结构

> 定位：代码阶段开工前的**结构冻结文档**。目录怎么建、新文件放哪、前后端怎么交互，以本文为准。
> 配套：`07_索引与总览.md`（执行步骤）、`AI代码编写规范.md`（包结构与代码约束）、`06_逐模块重构方案.md`（模块改点）。

---

## 1. 总体布局（单仓，前后端分离）

```text
D:\Code\project\cloud-sms\
├── README.md               # 入口
├── PROGRESS.md             # 进度台账（跨 PC）
├── AI代码编写规范.md        # AI 代码硬约束
├── docs\                   # 文档体系（不参与构建）
├── backend\                # 后端工程：Maven 多模块（9 模块）
├── frontend\               # 前端工程：Vue3 + Vite + TS
└── .gitignore              # 根级：忽略 node_modules/ target/ dist/ .idea 等
```

**关键决策**：

1. **单仓**：backend 与 frontend 同一个 git 仓库（仓库建在 cloud-sms 根），前后端联动改动一次提交。
2. **模块不改名**：后端 9 个模块沿用 `beacon-*` 原名（最小 diff、随时与旧项目对照），只是挪到 `backend\` 下。
3. **BFF = beacon-webmaster**：前端只与 webmaster 通信，webmaster 通过 Feign 编排 search/api/cache（不引入 Spring Cloud Gateway）。

## 2. 后端架构与目录

### 2.1 工程结构（backend\）

```text
backend\
├── pom.xml                 # 父 POM：com.cz:beacon-cloud:2.0.0-SNAPSHOT（版本治理中心）
├── beacon-common           # 共享底座：常量/模型(StandardSubmit等)/异常/工具/安全签名
├── beacon-api              # 接入层：短信发送入口 + 校验链 + 投递 MQ
├── beacon-strategy         # 策略层：过滤器链（黑名单/敏感词/限流/扣费/路由）
├── beacon-smsgateway       # 网关层：CMPP 2.0 over Netty + 回执处理
├── beacon-search           # 日志层：ES 8 写入/更新/检索/聚合
├── beacon-push             # 回调层：客户回执推送（延迟重试）
├── beacon-cache            # 支撑层：统一 Redis HTTP 服务（签名鉴权）
├── beacon-monitor          # 支撑层：xxl-job 队列/余额巡检
└── beacon-webmaster        # 后台层：运营后台 REST + BFF 编排
```

### 2.2 模块间调用关系

```text
                     HTTP/Feign
frontend ──(satoken)──▶ beacon-webmaster ──Feign──▶ beacon-search（检索/统计）
                             │     └──Feign──▶ beacon-api（代发短信 /sms/internal/single_send）
                             └──Feign──▶ beacon-cache（写缓存/重建）
外部客户 ──HTTP──▶ beacon-api ──MQ──▶ beacon-strategy ──MQ──▶ beacon-smsgateway ──CMPP──▶ 运营商
                                           ▲                      │
                        beacon-cache（Feign 读配置/通道/余额）◀─────┘
                                           └──MQ──▶ beacon-search ──ES──▶ 日志
                                           └──MQ──▶ beacon-push ──HTTP──▶ 客户回调
beacon-monitor ──xxl-job 调度──▶ 巡检 MQ 队列 + 客户余额 ──邮件告警
```

### 2.3 单模块内部结构（`com.cz.{module}`，新增代码必须遵守）

```text
src\main\java\com\cz\{module}\
├── {Module}StarterApp.java     # 启动类（模块名驼峰：Api/Search/Push/SmsGateway/Strategy/Cache/WebMaster/Monitor）
├── controller\                 # HTTP 入口：只做参数接收、校验、调 service
├── service\                    # 业务接口
├── service\impl\               # 业务实现
├── mq\                         # MQ 监听器 / 生产者
├── client\                     # Feign 客户端
│   └── dto\                    # Feign 传输对象（record）
├── config\                     # @Configuration / @ConfigurationProperties（record）
├── filter\                     # 过滤器 / 策略接口与实现（bean 名即策略名）
├── dto\ vo\ form\              # 数据载体（record，与 entity 严格分离）
├── util\                       # 无状态工具类
└── entity\ mapper\             # 持久层（仅 beacon-webmaster；Lombok @Data）
src\main\resources\
├── bootstrap.yml               # Nacos 引导（{app}-dev.yml 走配置中心）
└── mapper\*.xml                # MyBatis XML（仅 webmaster）
src\test\java\                  # 与 main 同构（JUnit 5）
```

**归属规则（新文件放哪）**：

| 内容 | 放哪 |
| --- | --- |
| 两个以上模块共用的模型/常量/工具 | `beacon-common` |
| 只被一个服务用的东西 | 该服务模块（禁止跨模块反向依赖） |
| Feign 接口 + 其 DTO | 调用方的 `client\` 包 |
| 消息体（MQ） | `beacon-common\model\`（跨服务流转） |
| 数据库实体 | 仅 `beacon-webmaster\entity\`（MySQL 真源唯一入口） |

## 3. 前端架构与目录（frontend\）

```text
frontend\
├── vite.config.ts              # dev 代理：/api → http://localhost:8080（webmaster）
├── package.json / tsconfig.* / tailwind.config.js
└── src\
    ├── main.ts                 # 入口（注册 Pinia/Router/ElementPlus）
    ├── App.vue
    ├── api\                    # 每个业务域一个 axios 模块，与后端 controller 一一对应
    │   ├── request 基础在 utils\
    │   ├── user.ts / role.ts / menu.ts / client.ts / channel.ts / black.ts
    │   ├── dirtyword.ts / limit.ts / phase.ts / smstemp.ts / sms.ts / search.ts ...
    ├── views\                  # 页面：按后端菜单 url 组织（如 sys\User.vue、client\client.vue）
    ├── router\index.ts         # 动态路由：登录后拉菜单树 → 拍平注册（现有逻辑保留）
    ├── store\                  # Pinia：userStore（token/userInfo/menuList）
    ├── layout\                 # 布局（侧边栏/顶栏）+ components\（ProTable/ProSearch/FormDialog）
    ├── utils\request.ts        # axios 封装：注入 satoken 头、401 统一跳登录
    └── styles\                 # tokens.scss（设计变量）+ element.scss
```

**前端约束**：

1. 页面组件与 `api\` 模块一一对应，禁止在页面里裸写 axios。
2. 动态路由由后端菜单树驱动（现有机制保留），新页面 = 新增 views 文件 + 后台菜单配置，不手写静态路由。
3. 生产构建 `npm run build` 产物 `dist\`，部署方案（Nginx 托管 + /api 反代）见阶段 F。

## 4. 前后端契约（沿 docs/learning/02 的认证约定）

| 项 | 约定 |
| --- | --- |
| 统一返回体 | `{code, msg, data}`，code=0 成功；业务错误 HTTP 仍 200（webmaster 改造后逐步收口） |
| 认证头 | `satoken: <token>`（Sa-Token；旧 `Authorization: Bearer` 废弃） |
| 401 处理 | axios 响应拦截：清 Pinia token → 跳 `/login?redirect=...`；并发 401 只提示一次 |
| 验证码 | `GET /sys/auth/captcha` → `{uuid, img(base64)}`；登录带 `uuid/code` |
| 代理 | dev：Vite `/api` → 8080；prod：Nginx 同路径规则 |
