## 步骤 0.1 · 基线拷贝 + 仓库初始化

**目标**：在 `backend/` 建出与旧项目一致的代码基线，建立独立 git 仓库。

**前置条件**：无。

**操作清单**

1. 创建目录：`$ROOT\backend`。
2. 拷贝基线（PowerShell，排除无关大目录）：

```powershell
robocopy $OLD $ROOT\backend /E /XD .git .idea .vscode node_modules target dist backups xxl-job
# 期望：264 目录、514 文件、0 失败
```

3. 初始化仓库并提交基线：

```powershell
cd $ROOT\backend
git init
# .gitignore 保留旧项目原有内容即可（已覆盖 target/、node_modules/ 等）
git add -A
git commit -m "chore: 基线拷贝（来自 beacon-cloud master c696c0c，未做任何修改）"
```

4. 前端：`robocopy $OLD\Frontend $ROOT\frontend /E /XD node_modules dist .vscode`。

> ⚠️ 单仓决策：git 仓库建在 `$ROOT`（cloud-sms 根），`backend/` 与 `frontend/` 为两个子目录，`.gitignore` 放根目录——前后端联动改动可一次提交。执行时若选"双仓"，需在 PROGRESS 记录该变更。

**执行命令**：见上（robocopy + git）。

**验收标准**

- [ ] `$ROOT\backend\pom.xml` 存在且与 `$OLD\pom.xml` 逐字节一致（`fc /b` 对比）
- [ ] `git log` 只有 1 个基线 commit
- [ ] （可选）基线状态下 `mvn -f backend\pom.xml clean install -DskipTests` 可复现旧构建

**常见坑**：robocopy 退出码 1~7 均为"有拷贝"的正常码；路径含中文无影响；不要用 `xcopy`（文件数上限问题）。

**回退**：删除 `$ROOT\backend`（或整个仓库）重新拷贝即可。

**提交产出**：commit `chore: 基线拷贝`。

## 步骤 0.2 · 父 POM 升级

**目标**：根 POM 切换到 Boot 3.2.12 + Cloud BOM，版本收口。

**前置条件**：0.1 完成。

**回退**：`git checkout -- pom.xml`。

**提交产出**：commit `refactor(pom): 升级 Boot 3.2.12 / Cloud 2023.0.3 / Alibaba 2023.0.3.2，版本收口`。

## 步骤 0.3 · 全局机械横切（javax / JUnit5 / pom 清理）

**目标**：一次性完成所有纯机械改动，后续模块深改不再被噪音打断。

**前置条件**：0.2 完成。

**操作清单**（三个子批次，每批一个 commit）

**批次 1 · javax→jakarta 换名**（35 处，仅三类；`javax.crypto/mail/imageio/sql` 不动）：

| 文件 | 改动 |
| --- | --- |
| beacon-common/.../util/SnowFlakeUtil.java:10 | `javax.annotation.PostConstruct` → `jakarta.annotation.PostConstruct` |
| beacon-api/.../filter/CheckFilterContext.java:11 | 同上 |
| beacon-api/.../controller/SmsController.java:28 | `javax.servlet.http.HttpServletRequest` → `jakarta.servlet.http.HttpServletRequest` |
| beacon-api/.../form/SingleSendForm.java、InternalSingleSendForm.java | `javax.validation.constraints.*` → `jakarta.validation.constraints.*` |
| beacon-cache/.../security/CacheAuthInterceptor.java:11-12 | `javax.servlet.http.*` → `jakarta.servlet.http.*` |
| beacon-smsgateway/.../controller/TestController.java:7 | `javax.annotation.Resource` → `jakarta.annotation.Resource` |
| beacon-monitor/.../config/XxlJobProperties.java:7、util/MailUtil.java:11 | `javax.annotation.*` → `jakarta.annotation.*` |
| beacon-webmaster（10 处，详见 `06_逐模块重构方案.md` 清单） | shiro/JwtFilter/KaptchaController 等 servlet；dto/advice/controller 的 validation；config/service 的 annotation |

**批次 2 · JUnit 4→5**（涉及 common/monitor/webmaster/api/strategy/push/search 全部 test 目录）：

| 旧 | 新 |
| --- | --- |
| `import org.junit.Test;` | `import org.junit.jupiter.api.Test;` |
| `import org.junit.Before;` / `@Before` | `import org.junit.jupiter.api.BeforeEach;` / `@BeforeEach` |
| `Assert.assertXxx(...)` | `Assertions.assertXxx(...)`（加 import `org.junit.jupiter.api.Assertions`） |
| `@Test(expected = X.class)` | `assertThrows(X.class, () -> ...)` |

**批次 3 · pom 版本清理**：删除各子模块写死的版本号——common 的 `spring-context 5.3.12`；strategy 的 `hutool-dfa 5.8.12`、ikanalyzer 版本；smsgateway 的 `netty-all 4.1.69`、`hippo4j 1.5.0`（依赖暂保留，3.1 步删除）；search 的 `elasticsearch 7.6.2` 系（2.1 步删）；monitor 的 `xxl-job 2.3.1`；webmaster 的 `shiro 1.4.0`（4.1 步删）、druid、mybatis、mysql 版本；**所有模块父引用 `1.0-SNAPSHOT` → `2.0.0-SNAPSHOT`、beacon-common 依赖版本 → `2.0.0-SNAPSHOT`**。

**执行命令**：本步骤只做文本替换，不编译（编译留到各模块步）；若想快速体检：

```powershell
cd $ROOT\backend
mvn -pl beacon-common -am compile -DskipTests   # 只验证 common 主代码
```

**验收标准**

- [ ] 全仓库 grep `import javax.` 只剩 `crypto/mail/imageio/sql` 四类
- [ ] 全仓库 grep `org.junit` 只剩 `org.junit.jupiter`
- [ ] 全仓库 grep `1.0-SNAPSHOT` 为 0
- [ ] 无任何业务逻辑被改动（`git diff --stat` 中每个文件只应有 import/注解行变化）

**常见坑**：IDE 全局替换 `javax.` → `jakarta.` 会误伤 `javax.crypto` 等，必须按上表逐类替换；`@Test(expected=...)` 旧语法 JUnit 5 不再支持，需改 `assertThrows`。

**回退**：三个批次分别 commit，出问题按 commit 逐个 revert。

**提交产出**：3 个 commit：`refactor(all): javax→jakarta 换名` / `refactor(test): JUnit4→JUnit5` / `refactor(pom): 子模块版本清理+版本号 2.0.0-SNAPSHOT`。
