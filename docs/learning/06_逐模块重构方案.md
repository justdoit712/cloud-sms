# 10 · 逐模块重构方案（9 模块 × 改点 / 风险 / 验收）

> 定位：代码重构阶段的**执行蓝图**。文档先行阶段产物，供审阅；确认后按此逐模块执行。
> 总原则：**只做技术升级**（版本/jakarta/框架替换/配置外置化），业务缺陷不修（见 `../02_项目详细分析总报告.md` 38 项，另行排期）。
> 每步动作：改代码 → `mvn -pl <模块> -am install -DskipTests`（保主代码编译）→ 迁移该模块单测 → 全量测试通过 → 提交 git。

## 执行策略（两步走：横切管机械，纵切管深入）

**为什么这样拆**：`javax→jakarta`、JUnit 4→5、pom 版本清理是纯机械、零决策、跨模块同构的改动，集中一次做完最高效；而 ES8 重写、Sa-Token、CMPP 等深改是每个模块独有的，必须按依赖顺序纵切。依赖顺序本身也是强制的（common 是所有模块的依赖）。

```text
第 0 步【全局横切，一次性完成】
  父 POM 升级 + 全项目 javax→jakarta 换名 + JUnit 4→5 + 子模块 pom 版本清理
  目标：此后每个模块的深改不再被机械噪音打断

第 1~9 步【按模块纵切，依赖顺序 + 简单优先】
  common → cache(简单热身) → search(ES8 重写) → api/strategy/push(批处理)
  → smsgateway(Netty/线程池) → monitor(xxl-job) → webmaster(Sa-Token，最大，内部再拆两段)
  每个模块收尾：编译验证 + 单测 + 一个干净 commit
```

模块顺序原则：**简单的先做**（cache、monitor 几乎只涉及 jakarta，用它们验证升级流程）；**复杂的后做**（webmaster 198 个文件，内部先"Sa-Token 替换"再"验证码接口化"）。

## 1. 父 POM（beacon-cloud/pom.xml）

**改点**
- parent：`spring-boot-starter-parent` 2.3.12 → **3.2.12**
- `<modules>` 不变（9 个）
- properties：删 1.8 编译目标；`spring-cloud.version=2023.0.3`、`spring-cloud-alibaba.version=2023.0.3.2`（注意属性名与引用一致，连字符写法）
- `dependencyManagement`：导入 Cloud 与 Alibaba BOM；新增 9 个三方组件版本管理（netty/hutool/elasticsearch-java/xxl-job/sa-token×2/mybatis/druid/ikanalyzer/kaptcha）

**风险**
- 属性名拼写不一致会导致 BOM 解析失败（历史教训：`spring-cloud-alibaba.version` vs `spring-cloud.alibaba.version`）
- 子模块旧 pom 写死的版本（如 spring-context 5.3.12、hutool 5.8.12）必须删掉，否则版本冲突

**验收**：`mvn -N install` 成功；`mvn help:effective-pom` 中 BOM 生效。

## 2. beacon-common

**pom**：删 spring-context 显式版本（Boot 管理 6.1.x）；保留 jakarta.annotation-api（Boot 管理 2.1.1）。
**代码**：
- `SnowFlakeUtil`：`javax.annotation.PostConstruct` → `jakarta.annotation.PostConstruct`
- `StandardSubmit` / `StandardReport`：移除 `@JsonSerialize/@JsonDeserialize`（jsr310）及 import（重构约定；Boot 3 Jackson 内置 JavaTimeModule）
- `CacheAuthSignUtil` 的 `javax.crypto.*` **不动**（JDK 自带）
- 测试：JUnit 5 迁移（含 CMPPSubmitRepoMapUtilTest / CMPPDeliverMapUtilTest 等）
**风险**：移除 jsr310 注解后，MQ 反序列化依赖各模块转换器注册 JavaTimeModule——各模块转换器在对应步骤统一改为注入 Boot ObjectMapper（见 §4.3）。
**验收**：`mvn -pl beacon-common install` 含测试全绿。

## 3. beacon-cache

**代码**：
- `CacheAuthInterceptor`：`javax.servlet.http.*` → `jakarta.servlet.http.*`（HandlerInterceptor 接口本身在 Spring 6 已切到 jakarta，import 同步）
- `WebMvcSecurityConfig`：确认 `WebMvcConfigurer` 实现与 Boot 3 兼容（接口不变）
- 其余（LocalRedisClient/NamespaceKeyResolver/CacheFacade/RedisConfig）API 兼容，预计零改动
**风险**：`RedisConfig` 的 `enableDefaultTyping` 在 Boot 3 + Jackson 2.15 可能直接启动报错（`Jackson2JsonRedisSerializer` 对 default typing 限制更严）——若报错，按"最小改动"改为显式类型序列化器或 `activateDefaultTyping` 白名单（此为编译/启动适配，属技术升级范畴）
**验收**：启动成功，`/v2/cache/hash/{key}` 带签名头返回 ResultVO。

## 4. beacon-search（ES 8 重写，最大单点）

**pom**：删 `elasticsearch-rest-high-level-client`、`elasticsearch`(7.6.2)、`mockito-inline`（Boot 3 starter-test 内置 inline mockito）；加 `elasticsearch-java`（父 POM 管理 8.19.21）。
**代码**（详见笔记 03 的逐方法映射）：
- `RestHighLevelClientConfig` → 新 `ElasticsearchClientConfig`：产出 `ElasticsearchClient` Bean（`JacksonJsonpMapper(bootObjectMapper)`），顺手补 connect/socket 超时（技术升级范畴）
- `ElasticsearchServiceImpl`：5 个方法按笔记 03 对照表翻译（index/exists/update/search/聚合）
- `SearchService` 接口、两个监听器、控制器**零改动**
**风险**：
- 聚合结果解析（`isSterms()`）是新客户端最易错点
- `UpdateResponse<Map>` 泛型与 `withJson` 的 Jackson 映射需实测
- 保持 index 幂等判定原语义（created-only 抛异常），缺陷后处理
**验收**：连本地 ES 8.x 跑通：写日志 → 查询 → 聚合；状态更新链路（TTL 10s 死信）验证 reportState 更新。

## 5. beacon-api / beacon-strategy / beacon-push（批量）

**api**：
- `SmsController`：`javax.servlet.http.HttpServletRequest` → jakarta
- `SingleSendForm/InternalSingleSendForm`：`javax.validation` → jakarta（注解不变）
- `CheckFilterContext`：`javax.annotation.PostConstruct` → jakarta
- RabbitMQ 转换器（RabbitMQConfig）：改为注入 Boot ObjectMapper（保 LocalDateTime 序列化，见笔记 01 §5.1）

**strategy**：
- pom：ikanalyzer 保持 2012_u6（版本父 POM 管理）；hutool-dfa 5.8.47（父 POM 管理）
- 代码预计零改动（无 javax 引用；`com.alibaba.cloud.commons.lang.StringUtils` 在 Alibaba 2023.0.3.x 仍存在）
- RabbitMQConfig 转换器同上改 Boot ObjectMapper
- 单测 JUnit 5

**push**：
- `RabbitMQConfig` 的 `Jackson2JsonMessageConverter`（无参构造，裸 ObjectMapper）→ 注入 Boot ObjectMapper（**必须改**，否则 StandardReport 的 LocalDateTime 运行期炸）
- 单测 JUnit 5；`ReflectionTestUtils` 在 Boot 3 照常可用
**验收**：三模块 `mvn install` 测试全绿。

## 6. beacon-smsgateway

**pom**：netty-all 版本删（父 POM 4.1.138.Final）；**删 hippo4j-spring-boot-starter**。
**代码**：
- `ThreadPoolConfig`：hippo4j 注解 → 标准 `ThreadPoolExecutor` Bean（Bean 名 `cmppSubmitPool`/`cmppDeliverPool` 不变，`SpringUtil` 取用方式不变；容量参数走 `${...}` 配置 + 显式默认值；拒绝策略 CallerRunsPolicy）——见笔记 04 §3
- `NettyStartCMPP`：硬编码 host/port/serviceId/pwd → `@ConfigurationProperties(prefix="cmpp")` 外置（重构约定；用 record，符合 AI代码编写规范）
- `TestController`：`javax.annotation.Resource` → jakarta
- RabbitMQ 转换器 → Boot ObjectMapper
- bootstrap.yml：新增 `cmpp.*` 配置段
**风险**：CMPP 协议缺陷（P2-P14）、断连丢消息（P24）等业务缺陷**不修**；`SmsGatewayStarterApp` 的 `@EnableDynamicThreadPool` 注解删除。
**验收**：连模拟 CMPP Server 跑通提交-应答-回执全链路。

## 7. beacon-monitor

**pom**：xxl-job-core 版本删（父 POM 2.4.2）。
**代码**：笔记 05 清单——`XxlJobProperties`/`MailUtil` 的 javax.annotation → jakarta；`javax.mail.*` 不动；单测 JUnit 5。
**验收**：注册到 xxl-job admin 2.4，手动触发两任务回执 200。

## 8. beacon-webmaster（Sa-Token + 纯 REST，收尾大项）

**pom**：删 shiro、java-jwt；加 `sa-token-spring-boot3-starter`、`sa-token-redis-jackson`、`spring-boot-starter-data-redis`、`commons-pool2`；druid → `druid-spring-boot-3-starter`（父 POM 管理 1.2.31）；mybatis-starter 版本删（父 POM 3.0.5）；mysql-connector-java 5.1.49 → **mysql-connector-j**（Boot 3 管理 8.3.0，坐标 `com.mysql:mysql-connector-j`，driver 类名不变 `com.mysql.cj.jdbc.Driver`——注意旧 yml 里写的是 `org.gjt.mm.mysql.Driver` 要改）
**代码**（详见笔记 02）：
- 删：`ShiroConfig`、`JwtFilter`、`JwtToken`、`ShiroRealm`、`JwtUtil`、`relam` 包
- 增：`SaTokenConfig`（SaInterceptor + 白名单=旧 anon 列表）、`StpInterfaceImpl`（getRoleList 查 sms_role、getPermissionList 查 sms_menu.url）
- `SmsUserController.login`：验证码校验 + `StpUtil.login(userId)` + 返回 `StpUtil.getTokenValue()`；新增 `/logout`
- `KaptchaController`：返回 `{uuid, img(base64)}` JSON，验证码文本存 Redis（TTL 5 分钟）
- 全局异常映射 NotLoginException→401、NotPermission/NotRole→403
- 角色名字符串判权处 → `@SaCheckRole` / `StpUtil.checkRole`（补授权闭环）
- 其余 controller 的 javax.validation/javax.servlet import 迁移；CORS 独立配置
**前端同步**（Frontend/，属文档阶段记录，代码阶段执行）：`utils/request.ts` Header `satoken`、401 处理、login 页调 `/sys/auth/captcha`。
**风险**：白名单核对（漏配=401 事故）；MyBatis 3.0.5 + Boot 3.2 组合需实测（`map-underscore-to-camel-case` 键不变）；kaptcha 0.0.9 在 Boot 3 的 Bean 装配需实测（servlet-api provided 不冲突）。
**验收**：登录拿 token → 带 `satoken` 头访问受保护接口；无权限返回 403；验证码接口返回 base64；Redis 出现 `satoken:` 键。
