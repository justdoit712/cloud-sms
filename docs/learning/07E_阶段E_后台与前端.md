# 07E · 阶段 E · 后台与前端（前后端同步推进）

## 同步总规则（贯穿本册）

1. **契约变更成对提交**：Header/返回体/接口路径/参数变化的改动，后端+前端在一次提交（或紧邻两次提交）内成对落地，禁止只提交一边。
2. **每小段必联调**：每完成一对改动，立刻 `npm run dev` + 浏览器实测，验收打勾后才进下一小段。
3. **联调环境**：后端 webmaster 起在 8080（Vite 代理目标），Redis 可连（Sa-Token 会话、验证码）。

## 小步划分（后端↔前端交错，共 4 步）

| 步 | 后端改动 | 前端改动 | 联调验收（浏览器实测） |
| --- | --- | --- | --- |

## 各小段详细操作

### E1 · 依赖替换与 Sa-Token 骨架（后端为主）

**后端**：
- pom：删 `shiro-spring-boot-web-starter`、`java-jwt`；`druid-spring-boot-starter`→`druid-spring-boot-3-starter`；`mysql-connector-java`(5.1.49)→`com.mysql:mysql-connector-j`；加 `sa-token-spring-boot3-starter`、`sa-token-redis-jackson`、`spring-boot-starter-data-redis`、`commons-pool2`。
- 删 5 类：`config/ShiroConfig`、`shiro/JwtFilter`、`shiro/JwtToken`、`relam/ShiroRealm`、`util/JwtUtil`。
- 增 `config/SaTokenConfig`：SaInterceptor + 白名单（= 旧 anon 列表：`/sys/auth/**`、`/sys/login`、`/logout`、静态资源）+ CORS（WebMvcConfigurer）。
- 增 `config/StpInterfaceImpl`：`getRoleList`（sms_user→sms_user_role→sms_role.name）、`getPermissionList`（sms_user→...→sms_menu.url 去 `.html`）。
- `application.yml`：sa-token 段（token-name=satoken / is-read-cookie: false / is-read-header: true / timeout=86400 / token-style=uuid）；driver 改 `com.mysql.cj.jdbc.Driver`。
- 暂不删 SmsUserController 里的旧 JWT 签发逻辑？**不**——本步直接一起改（见 E2），避免中间态；若想更稳，可先让 `/sys/login` 临时返回空 token 保证编译，E2 再补全。

**前端**：
- `utils/request.ts`：请求拦截器 Header 由 `Authorization: Bearer ${token}` 改为 `satoken: ${token}`。
- 此时登录接口还没返回 Sa-Token，页面登录会失败——**预期中间态，E2 完成后恢复**。

**联调验收**：后端能启动、无 Shiro 相关报错；旧前端登录失败属预期，记录后进入 E2。

### E2 · 登录 + 验证码（★ 前后端核心同步点）

**后端**（`SmsUserController.login` + `KaptchaController`）：
- `GET /sys/auth/captcha`：生成 Kaptcha 图 → 转 base64；文本存 Redis `captcha:{uuid}` TTL 300s；返回 `{uuid, img}`。
- `POST /sys/login`：校验 `uuid/code`（比对 Redis，用后即删）→ 密码比对（沿用 MD5+盐+1024）→ `StpUtil.login(user.getId())` → 返回 `StpUtil.getTokenValue()`。
- `POST /logout`：`StpUtil.logout()`。

**前端**（`views/login/Login.vue`）：
- 挂载时调 `/sys/auth/captcha` 展示 base64 图，点击图片刷新（uuid 同步更新）。
- 提交登录带 `{uuid, code, username, password}`；成功后 token 存 Pinia/localStorage。

**联调验收（必须浏览器实测）**：
- [ ] 登录页显示验证码；输错验证码 → 后端明确报错文案
- [ ] 正确账号密码 → 登录成功进 dashboard，network 面板确认请求头为 `satoken`
- [ ] 刷新页面仍保持登录（token 持久化生效）
- [ ] Redis 中出现 `satoken:login:token:...` 与 `captcha:{uuid}` 键（后一个登录后消失）

### E3 · 鉴权收口（前后端 401/403 行为）

**后端**：`WebmasterExceptionHandler` 增映射：`NotLoginException→401`、`NotPermissionException/NotRoleException→403`；四处角色字符串判权改注解/API（ClientBusinessController / CacheRebuildController / SearchController / SmsManageServiceImpl）。

**前端**：`request.ts` 响应拦截器：
```ts
if (code === 401) { userStore.clearToken(); router.push({ path: '/login', query: { redirect: current } }); }
// 并发 401 防抖：只弹一次提示
if (code === 403) { ElMessage.error(msg || '无权限'); }
```

**联调验收**：
- [ ] 清掉 localStorage token 后访问页面 → 自动跳登录页且回跳地址保留
- [ ] 普通角色账号点"角色管理/菜单分配"等管理入口 → 403 提示、页面不白屏
- [ ] 管理员账号全部页面可用

### E4 · 清理与全量点检

**后端**：grep `org.apache.shiro`/`com.auth0.jwt`/`javax.servlet` 归零；`mvn -pl beacon-webmaster -am install` 含测试全绿。

**前端**：全页面点检清单——用户/角色/菜单、客户管理（client/clientbusiness/clientchannel/userpay）、通道、策略链编排、网关过滤器、模板、敏感词、黑名单、号段、限流、灰度、图表、代发短信、检索。

**联调验收**：全部页面无 401/403 误伤；无任何页面裸调被拦截接口。

## 回退与提交

- **回退**：每个小段成对提交，出问题 revert 该小段（前后端一起回退）。
- **提交**（4 次成对提交）：
  1. `refactor(webmaster+frontend): Sa-Token 依赖替换与骨架，前端 Header 切 satoken`
  2. `feat(webmaster+frontend): 登录改造+验证码接口化，前端登录页对接（联调通过）`
  3. `refactor(webmaster+frontend): 鉴权收口 401/403，前端拦截跳转`
  4. `refactor(webmaster): 清理收尾；chore(frontend): 全页面点检`

## 常见坑

- **白名单漏配**：Sa-Token 拦截 `/sys/login` 本身 → 登录都进不去（对照旧 ShiroConfig anon 列表逐条核对）。
- **验证码 Redis 键不过期**：漏设 TTL → captcha 键堆积；用后未删 → 可重复用同一验证码。
- **前端 401 死循环**：登录接口本身返回 401 时不跳转（request.ts 需对 `/sys/login`、`/sys/auth/**` 豁免）。
- **token 过期但页面不跳**：Sa-Token timeout 与前端本地无感——靠任何接口 401 触发跳转，属预期行为。
