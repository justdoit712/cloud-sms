## 步骤 2.1 · beacon-search（ES 8 重写，全项目最大单点）

**目标**：ES 客户端整体替换为 `elasticsearch-java`，行为等价。

**前置条件**：1.1 完成；本机可连一个 ES 8.x（或先只编译+单测，联调放阶段 F）。

**操作清单**（对照 `03_ES8新JavaClient与search改造.md` 逐方法映射）

1. `pom.xml`：删 `elasticsearch-rest-high-level-client`、`elasticsearch`(7.6.2)、`mockito-inline`；加 `co.elastic.clients:elasticsearch-java`（版本父 POM 管）。
2. `RestHighLevelClientConfig` → 重写为 `ElasticsearchClientConfig`：

```java
@Configuration
public class ElasticsearchClientConfig {
    @Bean(destroyMethod = "close")   // RestClient 需显式关闭
    public RestClient restClient(@Value("${elasticsearch.hostAndPorts}") String hostAndPorts,
                                 @Value("${elasticsearch.username:}") String username,
                                 @Value("${elasticsearch.password:}") String password) {
        HttpHost[] hosts = parseHosts(hostAndPorts);   // 保留旧解析逻辑，加 trim
        RestClientBuilder builder = RestClient.builder(hosts)
                .setHttpClientConfigCallback(hc -> hc
                        .setDefaultCredentialsProvider(credentials(username, password))
                        .setDefaultRequestConfig(RequestConfig.custom()
                                .setConnectTimeout(2000)
                                .setSocketTimeout(30000).build()));
        return builder.build();
    }

    @Bean
    public ElasticsearchClient elasticsearchClient(RestClient restClient, ObjectMapper objectMapper) {
        // 复用 Boot 的 ObjectMapper（含 JavaTimeModule）
        return new ElasticsearchClient(new ElasticsearchTransport(
                new JacksonJsonpMapper(objectMapper), restClient));
    }
}
```

3. `ElasticsearchServiceImpl` 五个方法按 `03` 第 3 节翻译（index/exists/update/search/聚合），**保持原语义**（index 只认 created、update 先 exists 后 update、查询字段/高亮/聚合逻辑一致）。
4. 两个监听器、控制器、`SearchService` 接口：零改动。
5. 测试：`ElasticsearchServiceImplTest` 改为 mock `SearchService` 接口或 `ElasticsearchClient`（若 mock 新客户端太复杂，把断言下沉到 service 接口层）。

**执行命令**

```powershell
mvn -pl beacon-search -am install
```

**验收标准**

- [ ] 测试全绿
- [ ] `SmsWriteLogListenerTest / SmsUpdateLogListenerTest` 行为断言不变
- [ ] （阶段 F）连 ES 8 写入一条日志，`GET /sms_submit_log_{year}/_doc/{seq}` 可查，聚合接口返回 success/fail/waiting 计数

**常见坑**：聚合解析必须用 `isSterms()` 判别；`withJson` 传 `StringReader`；`UpdateResponse<Map>` 泛型第二参 `Map.class`；`hits().highlight()` 是 `Map<String,List<String>>`。

**回退**：`git checkout -- beacon-search`（本步独立，不影响其它模块）。

**提交产出**：`refactor(search): ES8 新客户端重写（index/exists/update/search/聚合等价迁移）`。

## 步骤 2.2 · beacon-api

**目标**：api 模块 Boot 3 编译测试通过。

**前置条件**：1.1 完成（api 依赖 common；与 cache 无编译依赖，可与 2.1 并行）。

**操作清单**

1. `RabbitMQConfig.jsonMessageConverter()`：改为注入 Boot ObjectMapper：

```java
@Bean
public MessageConverter jsonMessageConverter(ObjectMapper objectMapper) {
    return new Jackson2JsonMessageConverter(objectMapper);   // Boot 已注册 JavaTimeModule
}
```

2. `RabbitTemplateConfig`：confirm/return 回调保留（不修缺陷），仅确认 API 兼容。
3. `CheckFilterContext`（0.3 已换注解）：`@RefreshScope` + Map 注入在 Boot 3 行为不变。

**执行命令**：`mvn -pl beacon-api -am install`

**验收标准**：测试全绿；`ApiExceptionHandler` 的 `@RestControllerAdvice` 生效路径不变。

**常见坑**：Boot 3 下 `BindingResult` 必须紧跟 `@Validated` 参数位置（不变）；`@Validated` 在 Boot 3 需要 `spring-boot-starter-validation`（pom 已有）。
