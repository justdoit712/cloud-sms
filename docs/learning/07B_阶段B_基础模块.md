## 步骤 1.1 · beacon-common

**目标**：common 全绿（含测试），作为后续所有模块的依赖底座。

**前置条件**：0.3 完成。

**操作清单**

1. `StandardSubmit.java` / `StandardReport.java`：确认已无 `@JsonSerialize/@JsonDeserialize`（0.3 若未删则本步删，连同 3 行 import；字段保留 `LocalDateTime sendTime`）。
2. `SnowFlakeUtil.java`：确认 jakarta 注解（0.3 已做）。
3. `CMPPSubmitRepoMapUtil / CMPPDeliverMapUtil`（Caffeine）：API 兼容，零改动。
4. 测试类逐个过 JUnit 5（0.3 批次 2 已做，本步验证行为一致）。

**执行命令**

```powershell
cd $ROOT\backend
mvn -pl beacon-common -am install    # 含测试
```

**验收标准**

- [ ] BUILD SUCCESS（含全部测试，无 skip）
- [ ] `target/beacon-common-2.0.0-SNAPSHOT.jar` 生成
- [ ] 单测数量与旧版一致（对拍 `$OLD` 的 surefire 报告数）

**常见坑**：`JsonUtil` 的静态 ObjectMapper 在 Boot 3 的 Jackson 2.15 下对 `LocalDateTime` 需 JavaTimeModule——common 的 JsonUtil 已注册，确认不被改动；Caffeine 3.x 对 `expireAfterWrite` 用法不变。

**回退**：`git checkout -- beacon-common`。

**提交产出**：`refactor(common): jsr310 注解移除 + 测试迁移完成`。

## 步骤 1.2 · beacon-cache

**目标**：cache 服务在 Boot 3 下编译、测试通过。

**前置条件**：1.1 完成（依赖 common 2.0.0）。

**操作清单**

1. `CacheAuthInterceptor`：0.3 已换 jakarta servlet import；`HandlerInterceptor` 接口在 Spring 6 的实现签名不变。
2. `RedisConfig`：**重点验证** `Jackson2JsonRedisSerializer` + `enableDefaultTyping(NON_FINAL)` 在 Boot 3/Jackson 2.15 的启动表现——若启动报 `IllegalArgumentException: Could not resolve type id` 类错误，最小改动方案：改为 `activateDefaultTyping(mapper.getPolymorphicTypeValidator(), NON_FINAL)`；不改其它业务行为。
3. `CacheController / CacheStringController / CacheFacade / LocalRedisClient / NamespaceKeyResolver / RedisScanService`：API 兼容，预计零改动。
4. bootstrap.yml：`cache.client.auth` 等配置段不动。

**执行命令**

```powershell
mvn -pl beacon-cache -am install
```

**验收标准**

- [ ] 测试全绿（CacheFacadeTypedReadTest、CacheNamespacePropertiesTest 等）
- [ ] （可选）本地起 Redis 后 `mvn -pl beacon-cache spring-boot:run`，`/cache/set/{key}` 与 `/v2/cache/hash/{key}` 读写正常、签名头校验正常

**常见坑**：Boot 3 的 spring-data-redis 3.x 对 `RedisTemplate<String,Object>` 泛型校验更严，序列化器未配对会启动报错——按第 2 条方案处理。

**回退**：`git checkout -- beacon-cache`。

**提交产出**：`refactor(cache): Boot3 适配 + Redis 序列化器兼容`。
