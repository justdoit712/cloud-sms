# beacon-cloud 重构技术框架与前后端分离架构

> 本文档是重构项目的技术选型与架构冻结文档，覆盖升级版本、中间件、模块改造，以及**前后端分离**下的后端改造与接口契约。编码规范见 `16_新项目开发规范与JDK17特性约束.md`。

---

## 1. 架构总览（前后端分离）

```text
┌──────────────┐      /api (axios)      ┌─────────────────────────────┐
│  Frontend    │ ─────────────────────> │  beacon-webmaster (BFF)      │
│  Vue3 + Vite │   Token 头 + JSON      │  Sa-Token 认证 + 纯 REST     │
└──────────────┘                        │  业务编排 + Feign 调用        │
                                        └──────┬──────────────┬───────┘
                                               │              │
                                    Feign 调用   │              │ Feign 调用
                                               v              v
                                        beacon-search   beacon-api / 其他服务
```

关键决策：

1. **前后端分离**：前端独立工程（`Frontend/`，Vue3），后端只提供 REST API，不再渲染页面。
2. **不引入 Spring Cloud Gateway**（暂定）：由 `beacon-webmaster` 充当 BFF（Backend for Frontend），对外统一入口，内部通过 Feign 编排。理由：现有 `beacon-webmaster` 已有 `SearchController`、`SmsManageServiceImpl` 等编排逻辑，改动最小。后续确有需要再引入 Gateway。
3. **认证改 Token 态**：Shiro 会话态 → Sa-Token Token 态（Header 传递），适配前后端分离。

## 4. beacon-webmaster 后端改造要点（前后端分离核心）

### 4.1 Sa-Token 前后端分离模式

关闭 Cookie，Token 从请求头读取：

```yaml
sa-token:
  token-name: satoken          # Token 名称（Header / 参数名）
  timeout: 86400               # Token 有效期（秒）
  is-read-cookie: false        # 关闭 Cookie 读取（前后端分离必须）
  is-read-header: true         # 从 Header 读取 Token
  is-concurrent: true          # 同账号可多处登录
  token-style: uuid            # token 样式
```

登录接口返回 Token：

```java
@PostMapping("/login")
public ResultVO<String> login(@RequestBody @Valid LoginForm form) {
    // 校验验证码 + 账号密码
    StpUtil.login(userId);
    return Result.ok(StpUtil.getTokenValue());
}
```

鉴权拦截：注册 `SaInterceptor`，配合 `@SaCheckPermission` / `@SaCheckRole` 注解。

### 4.2 Shiro → Sa-Token 迁移

| Shiro 现有实现 | Sa-Token 对应 |
| --- | --- |
| `ShiroRealm` | `StpInterface`（`getPermissionList` / `getRoleList`） |
| `ShiroConfig` 过滤链 | `SaServletFilter` / `SaInterceptor` 注册 |
| `JwtFilter` / `JwtToken` | Sa-Token 默认 `StpLogic`（无需自定义） |
| `@RequiresPermissions` | `@SaCheckPermission` |
| `@RequiresRoles` | `@SaCheckRole` |
| `Subject.login/logout` | `StpUtil.login/logout` |
| Session 态 | Token + Redis 会话（`sa-token-redis-jackson`） |

### 4.3 移除与新增

**移除**：

- 静态页面渲染（`login.html`、模板引擎等）。
- Shiro 依赖与相关配置。

**新增**：

- CORS 配置（或依赖 Vite 代理，生产环境需网关/Nginx 处理）。
- 统一返回体 + 全局异常处理器（HTTP 状态码与业务 code 约定，见第 5 节）。
- 验证码接口化（见 4.4）。
- 退出登录接口（`StpUtil.logout()`）。

### 4.4 验证码接口化

前后端分离下，Kaptcha 改为「生成图片 → 返回 base64 + 唯一标识 → 登录时校验」：

```text
GET  /captcha        -> { uuid, img(base64) }
POST /login          -> { uuid, code, username, password }
```

- 验证码文本存 Redis（key 含 uuid，带 TTL），登录时取出比对。
- 保留 `KaptchaConfig`，改造 `KaptchaController` 返回 JSON。

## 5. 前后端接口契约

### 5.1 统一返回体

所有后端 REST 接口返回：

```json
{ "code": 0, "msg": "", "data": {} }
```

- `code = 0` 成功，非 0 失败。
- `msg` 为提示文案，`data` 为业务数据。

### 5.2 认证约定

- 前端登录成功后，将 Token 存入 localStorage/Pinia，并在 axios 请求拦截器统一注入 Header：`satoken: <token>`。
- 后端返回 `401` 时，前端 axios 响应拦截器统一清理登录态并跳转登录页（保留回跳地址）。
- 禁止并发多个 `401` 弹出多条错误提示。

### 5.3 前端 axios 约定

- 请求拦截器：注入 Token。
- 响应拦截器：`code === 0` 放行；`401` 跳登录；其他非 0 统一 `Message.error(msg)`。
