# beacon-cloud 新项目开发规范与 JDK 17 特性约束

> 本文档是重构后 `beacon-cloud` 的编码与框架使用约束，目标是：在升级到 JDK 17 / Spring Boot 3 后，**统一新代码风格**，并在合适场景下**优先使用 JDK 17 新特性**（record、sealed、switch 表达式、pattern matching 等）。

---

## 0. 文档定位

本文档回答三个问题：

1. 新项目的基础基线是什么（JDK / Boot / 代码风格）。
2. 哪些场景**必须**使用 JDK 17 新特性，哪些场景**禁止**使用。
3. 各类数据载体（实体 / DTO / VO / 表单 / 消息对象）该如何选型。

约定关键词：

- **必须**：强制遵守，review 时违反需修改。
- **推荐**：优先采用，除非有明确理由。
- **禁止**：不允许使用。

---

## 1. 基线约定

| 项 | 约定 |
| --- | --- |
| JDK | 17 (LTS)，编译目标 `--release 17` |
| 构建 | Maven 3.9.x，父 POM 统一管理版本 |
| 框架 | Spring Boot 3.2.x / Spring Cloud 2023.0.x |
| 编码 | UTF-8，`-parameters` 编译参数（Boot 父 POM 已默认开启） |
| 风格 | 无特殊要求时遵循 `beacon-common` 现有包结构 |

---

## 2. 核心原则

1. **不可变优先**：能做成不可变的数据载体（DTO/VO/表单/配置）一律用 `record`，禁止手写可变 getter/setter 类。
2. **明确分工**：`record` 负责「不可变数据载体」，Lombok 仅保留给「必须可变」的持久化实体等少数场景（见第 4 节）。
3. **能表达就不写 if**：类型分派用 `sealed` + `switch` 表达式，类型判断用 pattern matching。
4. **旧代码不动则不强改**：迁移存量代码时不要求一次性重写，但**新增代码必须遵守本规范**。

---

## 3. JDK 17 新特性使用规范

### 3.1 Record（不可变数据载体）

#### 必须使用 record 的场景

- 请求表单（Form）、请求体 DTO、响应 VO、Feign 请求/响应对象。
- 配置快照、只读的值对象（如策略过滤器之间传递的中间结果）。
- 只读的查询参数封装对象。

```java
// 必须：请求表单用 record
public record SingleSendForm(
        @NotBlank(message = "apikey不能为空") String apikey,
        @NotBlank(message = "mobile不能为空") String mobile,
        @NotBlank(message = "text不能为空") String text,
        Integer state,
        String uid
) {}
```

```java
// 必须：响应 VO 用 record
public record SmsSendResultVO(int code, String msg, String uid, String sid) {
    public static SmsSendResultVO ok(String uid, String sid) {
        return new SmsSendResultVO(0, "", uid, sid);
    }
}
```

#### 禁止使用 record 的场景

1. **MyBatis 持久化实体**：MyBatis 需要无参构造 + 可变 setter，record 无法满足，禁止使用 record 作为 entity / mapper 返回实体。
2. **跨模块可变流转对象**：如 `StandardSubmit`、`StandardReport` 在链路中会被多次 `setXxx` 修改，禁止改为 record。
3. **需要继承或需要子类扩展的类**：record 是 final 的，无法继承。
4. **需要可变状态（被多个过滤器先后写入）的上下文对象**：如 `StrategyFilterContext` 里流转的对象。

#### record 的校验写法

校验逻辑放在紧凑构造器（compact constructor）中：

```java
public record InternalBalanceDebitRequest(
        Long clientId, Long fee, Long amountLimit, String requestId) {
    public InternalBalanceDebitRequest {
        if (clientId == null || clientId <= 0) {
            throw new IllegalArgumentException("clientId must be positive");
        }
        if (fee == null || fee <= 0) {
            throw new IllegalArgumentException("fee must be positive");
        }
    }
}
```

字段级 Bean Validation 注解可直接写在 record 组件上（配合 `@Valid`）。

#### record 与 Jackson

Spring Boot 3 内置 Jackson 2.15+，**原生支持 record 序列化/反序列化**，无需额外配置。RabbitMQ 消息若用 record，需确认 `Jackson2JsonMessageConverter` 能正确反序列化（Boot 3 默认可行）。

#### record 与 @ConfigurationProperties

Spring Boot 2.6+ 支持构造器绑定，配置类**推荐**用 record：

```java
@ConfigurationProperties(prefix = "cache.client.auth")
public record CacheAuthProperties(boolean enabled, String caller, String secret) {}
```

### 3.2 Sealed Class / Interface（封闭类型）

#### 适用场景

- 封闭的「结果类型」，如成功/失败二元结果、命令执行结果。
- 封闭的枚举式分支，需要编译器保证分支完备。

```java
// 推荐：结果类型用 sealed interface + record 实现
public sealed interface BalanceCommandResult
        permits BalanceCommandResult.Success, BalanceCommandResult.Failure {

    record Success(long balance, Long amountLimit) implements BalanceCommandResult {}
    record Failure(int code, String message) implements BalanceCommandResult {}

    default boolean isSuccess() {
        return this instanceof Success;
    }
}
```

配合 `switch` 表达式可让编译器校验分支完备（见 3.4）。

#### 注意

- `sealed` 的 `permits` 子类必须与父类同模块（或同包，取决于配置），不适合跨服务开放的 SPI 接口。
- 运行时由 Spring 容器注入的策略接口（如 `StrategyFilter`）**不推荐**用 `sealed`，因为实现类分散且需要动态扩展。

---

### 3.3 Pattern Matching for instanceof（模式匹配）

#### 必须使用

`instanceof` 后紧跟强制转换的场景，一律改为模式匹配：

```java
// 禁止
if (obj instanceof String) {
    String s = (String) obj;
    // ...
}

// 必须
if (obj instanceof String s) {
    // 直接使用 s
}
```

多条件判断推荐合并：

```java
if (obj instanceof ClientBalance b && b.getBalance() != null && b.getBalance() > 0) {
    // ...
}
```

---

### 3.4 Switch 表达式与增强 switch

#### 必须使用

状态机、枚举/整型多分支返回值、结果分派，优先用 `switch` 表达式：

```java
// 禁止：冗长 if-else 返回值
String stateName;
if (state == 0) { stateName = "waiting"; }
else if (state == 1) { stateName = "success"; }
else { stateName = "fail"; }

// 必须：switch 表达式
String stateName = switch (state) {
    case 0 -> "waiting";
    case 1 -> "success";
    default -> "fail";
};
```

与 `sealed` 配合时，`switch` 表达式可省略 `default`，由编译器保证完备性：

```java
String message = switch (result) {
    case BalanceCommandResult.Success s -> "ok, balance=" + s.balance();
    case BalanceCommandResult.Failure f -> "fail: " + f.message();
};
```

### 3.5 Text Block（文本块）

#### 必须使用

SQL、JSON、长字符串模板等，用文本块替代字符串拼接：

```java
// 禁止
String json = "{\"clientId\":\"" + clientId + "\",\"fee\":" + fee + "}";

// 必须
String json = """
        {
          "clientId": "%s",
          "fee": %d
        }
        """.formatted(clientId, fee);
```

MyBatis XML 里的 SQL 不适用本规则（XML 天然多行）。

---

### 3.6 var（局部变量类型推断）

#### 推荐（但克制）

仅当类型名冗长、右侧表达式已充分表达类型时使用：

```java
// 推荐
var result = cacheFacade.hGetAll(CacheKeyConstants.CLIENT_BUSINESS + apiKey);

// 禁止：类型不明确时用 var，降低可读性
var x = getSomething();
```

规则：`var` 用于「右手边类型显而易见」的场景；方法签名、字段声明、公共 API **禁止**用 `var`。

---

### 3.7 Stream.toList() 与不可变集合工厂

#### 必须使用

- 收集到 `List` 且不需要可变时，用 `Stream.toList()`（JDK 16+，返回不可变 List）：

```java
// 推荐
List<String> names = list.stream().map(String::trim).toList();

// 禁止（除非确实需要可变 List）
List<String> names = list.stream().map(String::trim).collect(Collectors.toList());
```

- 小量固定元素集合用工厂方法：

```java
List<String> filters = List.of("apikey", "ip", "sign");
Set<String> domains = Set.of("client_business", "channel");
Map<String, String> m = Map.of("k1", "v1", "k2", "v2");
```

注意：`List.of/Set.of/Map.of/Stream.toList()` 都是**不可变**的，不能往里面 `add`，否则抛 `UnsupportedOperationException`。

## 4. Lombok 与 record 的分工

重构后项目**保留 Lombok**，但收窄使用范围：

| 场景 | 选型 | 说明 |
| --- | --- | --- |
| 持久化实体（MyBatis entity） | Lombok `@Data` | 需无参构造 + 可变 setter |
| 跨模块可变流转对象（StandardSubmit 等） | Lombok `@Data` | 链路中反复 set |
| 请求表单 / 响应 VO / DTO | **record** | 不可变，禁用 Lombok |
| 配置快照 / 值对象 | **record** | 不可变 |
| 结果类型 | **sealed interface + record** | 封闭分支 |

禁止在新写的 DTO/VO/Form 上继续使用 `@Data`。

## 5. 分层与包结构约束

沿用现有 `com.cz.{module}` 结构，新代码遵守：

```text
com.cz.{module}
├── controller      # HTTP 入口，只做参数接收、校验、调用 service
├── service         # 业务接口
├── service.impl    # 业务实现
├── mq              # MQ 监听器 / 生产者
├── client          # Feign 客户端及其 dto
├── config          # 配置类（@Configuration / @ConfigurationProperties）
├── filter          # 过滤器 / 策略（策略模式接口 + 实现）
├── dto / vo / form # 数据载体（record）
├── util            # 无状态工具类
└── entity / mapper # 持久化实体与 Mapper（Lombok @Data）
```

约束：

- Controller 禁止写业务逻辑，只做编排。
- DTO/VO/Form 用 `record`，与 entity 严格分离，禁止把 entity 直接暴露给 Controller。
- 跨服务传输对象优先复用 `beacon-common`，避免重复定义。

## 7. 不可变性与序列化注意

1. `record` 与 RabbitMQ：作为消息体时，确保 `Jackson2JsonMessageConverter` 正常反序列化；如果对象在消费者侧需要修改字段，**不要用 record**（改回 `@Data` 类）。
2. `record` 是 `final`，无法被代理（如 AOP 动态代理），涉及代理增强的对象不要用 record。
3. `record` 的字段不要使用可变集合作为组件并直接暴露（record 只做浅不可变），需要真正不可变时在构造器里 `List.copyOf`。
4. `List.of` 不允许 `null` 元素；有 `null` 场景用 `Arrays.asList` 或可变集合。

## 8. Review 检查清单

新代码提交前自查：

- [ ] 新增 DTO/VO/Form 是否用 record，而非 `@Data` 类？
- [ ] 是否存在 `instanceof` + 强制转换未用模式匹配？
- [ ] 多分支返回值是否用 `switch` 表达式？
- [ ] 是否用 `Stream.toList()` 替代 `collect(Collectors.toList())`？
- [ ] entity 是否仍是普通类（未误用 record）？
- [ ] 可变流转对象是否保持 `@Data`（未误改 record）？
- [ ] 是否有 `var` 被用于公共 API 或字段？
- [ ] 是否新增了不必要的 Lombok 注解（如 DTO 上的 `@Data`）？
- [ ] 配置属性是否用 record + `@ConfigurationProperties`？
